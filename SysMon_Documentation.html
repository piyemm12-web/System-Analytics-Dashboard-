1. Executive Project Summary

SysMon is a production-grade, real-time system telemetry and process monitoring dashboard. Built with a modular micro-telemetry kernel in Go and a low-latency UI in React and TypeScript, SysMon provides deep observability into hardware metrics, storage volumes, network throughput, and active OS threads with minimal memory and CPU overhead.

3. Technology Stack & Technical Highlights

Backend: Go (Golang)

Utilizes gopsutil/v3 to query cross-platform kernel counters (CPU, RAM, Disks, Network, OS Processes, Temperatures). Uses background goroutines with mutex locks and concurrency semaphores (16 workers) to avoid blocking HTTP requests.

Frontend: React + Vite + TypeScript

Vite 5 with SWC compilation provides instantaneous hot module replacement. Built with custom SVG area and polyline curves to render continuous processor activity baselines with 60 FPS fluidity and zero bloated chart library overhead.

Telemetry Engine Features:

  • Safe In-Memory Ring Buffer: A 288-point sliding window maintains 24-hour historical telemetry data at 5-minute aggregation intervals with real-time 10-second updates.
  • Concurrent Process Scanner: Gathers top 50 active processes sorted by CPU and memory consumption. Uses process cache preservation and context deadlines (1500ms timeout) to prevent hung process inspection.
  • Process Termination API: Provides a guarded /api/processes/kill endpoint supporting both query parameters and JSON body payloads to terminate runaway processes.

4. REST API Endpoint Reference

Endpoint Method Description Sample Payload Structure
/api/stats GET Full snapshot of CPU, RAM, Disks, Network, Uptime, and Temp {"cpu":{...},"memory":{...},"disks":[...],"network":{...},"uptime":41230}
/api/cpu-history GET Historical sampling points for timeline rendering [{"timestamp":"14:05","cpuUsage":24.5,"ramUsage":58.2}, ...]
/api/processes GET Top 50 running OS processes sorted by CPU load [{"pid":1402,"name":"chrome.exe","cpuPercent":3.4,"memoryPercent":1.2}, ...]
/api/processes/kill POST / GET Terminates a target process by PID Query: ?pid=1234 or Body: {"pid":1234}
/health GET Service heartbeat status check {"status":"healthy"}

5. User Interface Views & Visual Modules

  • Overview View: Aggregated telemetry cards with gauge meters (CPU core load, RAM saturation, storage volume, outbound network) alongside continuous 10s-sampled SVG curve charts.
  • CPU Core View: Per-core utilization bar matrix (displaying all available logical cores) plus 1-min, 5-min, and 15-min scheduler load averages.
  • RAM Space View: Granular visual breakdown between active physical RAM (used vs total) and virtual paging swap space.
  • Partitions View: Mounted file-system volumes showing absolute capacities, mount points (e.g. C:\, /dev/sda), and percentage bars.
  • Network IO View: Byte counters and cumulative packet transmission matrices (TX/RX).
  • Tasks (Process Manager): Full process table with instant search filtering, bi-directional column sorting, and process termination dispatch.

6. Step-by-Step Running Guide

Prerequisites Installed: Go 1.22+ and Node.js v18+ with npm.

Step 1: Launch the Backend Service

Open a PowerShell terminal in the repository root and run:

cd c:\Users\LENOVO\sysmon\backend
go run cmd/server/main.go

Or alternatively execute the pre-built binary:

cd c:\Users\LENOVO\sysmon\backend
.\server.exe

The backend will initialize and output: 🚀 Modular Telemetry Kernel online mapping infrastructure to port :8080.

Step 2: Launch the Frontend Development Server

Open a second terminal window and run:

cd c:\Users\LENOVO\sysmon\frontend
npm.cmd run dev
PowerShell Note: If PowerShell displays a script execution policy error for npm, use npm.cmd run dev or launch via Command Prompt (cmd /c npm run dev).

Step 3: Access the Live Dashboard

Open your browser and navigate to:

http://localhost:3000

The dashboard connects immediately to the Go backend bridge on port 8080 and streams real-time telemetry.
