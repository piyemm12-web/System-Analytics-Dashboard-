3. "How It Works" - Whiteboard Candidate Script
Phase 1: Hardware Metric Collection (Go + Syscalls)
Spoken Script: "In the backend, a background goroutine ticks every 10 seconds. Using gopsutil bindings, it samples multi-core CPU usage, RAM utilization, disk I/O, network counters, and host temperatures. Because HTTP/WebSocket handlers read metrics while the background ticker writes them, I synchronize access using a sync.RWMutex. Readers grab an RLock() concurrently without contention, and writes acquire an exclusive Lock(). We defensively copy slice buffers before returning them to guarantee zero data races."
Phase 2: High-Performance Process Scanner
Spoken Script: "Scanning 200+ processes every 3 seconds can freeze a system. I resolved this using three techniques:
  1. Worker Pool Semaphore: Bounded concurrency using a buffered channel (chan struct{}, 16) to prevent OS context switching.
  2. Context Deadlines: Wrapped calls in context.WithTimeout(1500ms) to drop non-responsive process reads.
  3. Pointer Cache: Maintained an in-memory map of *process.Process structs, purging only terminated PIDs to eliminate Garbage Collection memory churn."
Phase 3: Time-Series Storage Pipeline (PostgreSQL)
Spoken Script: "Telemetry data points are ingested into PostgreSQL using connection pooling via Go's pgx. For 24-hour graphing, sending tens of thousands of raw points would overwhelm the client. The backend executes downsampling aggregation queries in SQL (grouping by 5-minute buckets), reducing JSON payload sizes by over 70% and keeping response times strictly under 120ms."
Phase 4: Real-Time WebSocket Streaming & Frontend SVG Engine
Spoken Script: "Instead of HTTP polling, a persistent WebSocket hub pushes telemetry frames to connected clients under 50ms latency. On the frontend, custom React hooks receive these frames. Rather than importing bulky charting libraries, I built an SVG vector generator that translates time-series coordinates directly into SVG path coordinates (M x,y L x,y Z) with hardware-accelerated linear gradient fills, maintaining a constant 60 FPS."

5. Core Technical Fundamentals & Interview Trap Questions
Interview Question Concise Engineering Answer
"Goroutines vs OS Threads: Why is Go so fast?" Goroutines are user-space green threads multiplexed onto OS threads by the Go runtime scheduler (M:N model). They start with a tiny 2KB stack (vs 1-2MB for OS threads) and switch contexts without invoking expensive kernel ring-0 transitions.
"Why sync.RWMutex over a standard sync.Mutex?" A standard Mutex serializes all callers. In a monitoring dashboard, 95% of operations are read-only client queries. RWMutex permits infinite concurrent readers (RLock) simultaneously, blocking only during short write ticks.
"How did you prevent memory leaks in WebSockets?" Maintained a thread-safe hub map of active client connections. Implemented ping/pong heartbeats: if a client drops ungracefully without sending a TCP close frame, the ping timeout evicts the connection pointer and closes the socket.
"Why custom SVG graphs instead of Chart.js / Recharts?" Avoided 200KB+ of external JavaScript bundle overhead. Inline SVGs offload vector coordinate rendering directly to browser GPU/layout engines, giving pixel-perfect responsive scaling without canvas repainting lags.
"How would you scale this to 1,000 servers?" Decouple the architecture: run the Go collector as a lightweight daemon agent on each server pushing metrics via gRPC to a distributed Kafka ingestion stream, backed by TimescaleDB / Prometheus and a central Grafana/React cluster dashboard.
6. Mathematical Coordinate Mapping in Frontend SVG
How Graph Points Are Calculated on Screen
When asked how custom SVG paths are plotted from an array of metric data points:

X Coordinate = (index / (totalPoints - 1)) * viewBoxWidth
Y Coordinate = height - (percentage / 100) * (height - padding)

The path string is composed as: M 0,height L x1,y1 L x2,y2 ... L width,height Z and filled with a linear gradient.
